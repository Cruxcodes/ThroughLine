## Cognitive habits

- **Defers to expert taste, then refines with precision** [Blossoming] — asked "which one is better for a mental health app" instead of picking from a menu; once shown the recommendation, delivered four specific, non-overlapping corrections in a single pass (watercolour blending, warmer label, breathing highlight, consistent dots). Doesn't deliberate in the abstract — wants a concrete proposal to react against.
- **Low process tolerance** [Blossoming] — said "implement it" twice, skipped formal design review, pushed past the brainstorming checklist. Treats process as overhead when the direction is clear. Doesn't need sign-off on every step; trusts the builder's instinct.
- **Hackathon-scoped mode** [Germinating → Blossoming] — confirmed again: "so hat can i add in an our" (typoing at speed), confirms time-bounded mode. The speed and low-ceremony are intentional, not accidental.
- **Visual-first problem framing** [Germinating] — when asked about interaction model, picked the most ambient option (scroll-linked highlight). Prefers things that feel right over things that are maximally functional. The feel is the feature.
- **Image-driven verification** [Blossoming] — used screenshots as the source of truth twice in one session. "does the app fulfill this", "does it match any of this now". Builds to spec by iterating against visual evidence, not prose.

## Engineering habits

- **Bleeding-edge stack adopter** [Germinating] — Expo 56, React Native 0.85.3, React 19.2.3, Hermes, Bridgeless+Fabric. Stays on the newest version of everything. Doesn't wait for stability signals.
- **AI-paired builder** [Blossoming] — uses Claude (Sonnet 4.5) for the backend AI pipeline, runs the code agent (Claude Code) as the primary development tool. The agent does the scaffolding; the builder directs and refines.
- **No test-first observed** [Seeding] — no test-driven patterns in this session. May write tests after or not at all in hackathon mode. Needs confirmation for general practice.
- **Commit style: descriptive, multi-clause** [Germinating] — from git history: "Implement support for fetching tips and grounding techniques in the mobile app. Introduce new components..." Full sentences, narrate what changed. Not atomic single-concern commits; bundles related work.
- **Incremental, additive refactoring** [Blossoming] — when fixing the brief structure, specifically asked "don't change the current application, build on it". Values continuity. Doesn't delete and rewrite — mutates in place. This is a constraint preference, not just pragmatic.
- **Bug-driven, not test-driven** [Germinating] — found voice recording bug through UX, ran /doctor to surface JSON error. Debugging is reactive, not preventive. Has a quality instinct but expresses it post-facto.
- **Fast iteration on prompts** [Germinating] — edited AI prompt directly for brief sections. Understands prompt engineering as just another config file to edit. Doesn't treat it as magic; it's material.

## Relational mode

- **Terse, expects inference** [Blossoming → Confirmed] — one-word answers ("him", "english", "hackathon", "remove it", "done"), redirects open questions to specific ones ("which one is better"), doesn't elaborate unprompted. Expects the agent to read between the lines. Typos ("so hat can i add in an our") are signal — moving too fast to correct.
- **Trusts the agent's recommendation when it earns it** [Germinating] — accepted the heat strip recommendation initially (I argued for it), then overrode with "use the weather map" when they had a different instinct. Will defer when the argument lands, override when it doesn't. The override is quiet, not argumentative.
- **Screenshot as conversation** [Blossoming] — drops screenshots, asks "does it match", "does the app fulfill this". Uses visual artifact as the shared reference point. Don't explain back — show back.
- **No small talk, no meta** [Blossoming] — doesn't ask "how are you", doesn't say "thanks". When done with a fix, moves to next question immediately ("so hat can i add in an our"). The relationship is tool-like, but the work is creative.

## Preferences

- **Visual language**: watercolour, gradient, ambient — not geometric, not gridded, not data-dense
- **Communication style**: minimal words, maximal signal. No pleasantries, no process.
- **Decision method**: "show me something concrete, I'll tell you what's wrong with it"
- **Tool trust**: uses AI agents for scaffolding and exploration, retains authority on aesthetic and safety calls
- **Fix orientation**: wants the bug fixed, not a lecture on how it happened. "Help me fix the issues" — not "explain why this happened". Accepts brief explanation, moves on.
- **Incremental validation**: after brief changes, immediately checks against spec via screenshot. Doesn't assume done until visually verified.

## Hard limits

- No clinical jargon or scoring in user-facing UI
- No gamification (streaks, scores, dashboards)
- No process overhead when direction is clear
- No generic recommendations — everything must be context-specific

## Activation triggers

- "Show me what you'd recommend" — the builder wants a concrete proposal to react to, not a menu
- Visual/aesthetic decisions — these get the most engaged, precise feedback
- Speed-oriented framing — "implement it", "go for it", "try again"
